# M5 CloudDrive2 实现矩阵

- 完成日期：2026-08-13
- 状态：已完成
- 默认测试：纯离线 Mock 与临时 SQLite，不访问公网或生产目录

## 1. 协议与配置

CloudDrive2 适配器使用与 M1 实例匹配的官方 gRPC 1.0.14 协议子集。生成客户端与 proto 一同打包，不依赖未公开 REST 接口。

下列值均属于实例配置，不绑定开发环境：

- endpoint、API Token或用户名/密码认证；
- TLS 校验与可选 CA；
- 当前凭据可见的 API 根目录、Profile 子目录和连接测试子目录；
- 通用 RPC 与离线任务查询 Deadline；
- 轮询间隔、关注阈值和 CD2 提交后目录检查延迟；
- 稳定观察次数，以及递归文件树的深度和条目上限。

受限 Token 把宿主目录映射为 API 虚拟根 `/` 时，Tuntu 只使用虚拟路径。路径必须为规范化 POSIX 绝对路径，Profile 子目录不能越级；CD2 返回目标目录外的路径也会被拒绝。

## 2. 提交与错误语义

| 外部结果 | Tuntu 行为 |
|---|---|
| `success=true` | 保存提交前目录基线并进入 `submitted` |
| 明确同步拒绝 | 进入 `failed`；上层 Run 可决定是否尝试下一候选 |
| 115 `10008` 已存在 | 进入 `attention_required`，不伪装为新提交成功 |
| Deadline、Unavailable、Cancelled | 保持 `submitting` 和原 BTIH 幂等锁，结果标记为未知 |
| 鉴权、路径或其他明确客户端错误 | 保存脱敏错误分类，不记录秘密或原始 magnet 参数 |

提交前先在 SQLite 中占用“CD2 实例 + 内容”和“CD2 实例 + BTIH”。结果未知不会释放占位，也不会切换候选。重试建立新代次并关联旧任务；非失败状态强制重提和人工完成都要求二次确认并写审计事件。

## 3. 状态与完成判定

状态机支持 `submitting → submitted → downloading → completed`，也允许 CD2 直接给出可靠完成信号。明确外部错误进入 `failed`；轮询或文件树读取错误不覆盖最后可靠状态，超过配置阈值才进入 `attention_required`。

完成证据按强度选择：

1. `ListOfflineFilesByPath` 按 BTIH 返回可靠状态时直接映射。
2. 任务接口超时或无匹配项时，比较提交前目录基线与当前文件树。
3. 新增/变化的非空文件集合必须连续保持配置次数不变，且次数不少于两次，才自动完成。
4. 文件回退期间对同一目标目录做互斥，观察到任务顶层路径后只跟踪这些路径，减少并发文件误归属。
5. 状态、证据、错误、外部引用和完成观察状态全部持久化，应用重建服务对象后可继续判定。

## 4. 验证结果

- 86 项离线测试通过，另有 29 项参数化子测试。
- 其中 38 项定向覆盖 CD2 配置、路径、认证、提交错误、任务信号、状态机、目录基线、稳定观察、目标目录互斥、重试、人工完成与迁移。
- 最小公开 `GetSystemInfo` 线协议探针返回登录、就绪、无错误。
- 合法公开资源的真实提交、稳定文件确认与重复提交行为已在 M1 完成；M5 未再次创建外部下载任务。

M6 将在此基础上加入 Run 编排、定时轮询和进程重启恢复，不修改 M5 的完成语义。

> M6 后续加固：批量 Run 不能在文件归属出现前共享同一路径，否则第二个任务会被 M5 的安全锁阻塞。现采用 `Profile 目录 / 完整 BTIH` 隔离，并扩展官方 `CreateFolder` RPC；这强化了 M5 完成语义，但要求 CD2 Token 具备创建文件夹权限。

> RC1 实机复验（2026-08-13）：受限 Token 补充 `CreateFolder` 最小权限后，连接测试成功创建独立目录。当前实现随后提交 WebTorrent 合法开放影片，保存到“Profile / 完整 BTIH”目录，并由文件变化和连续两次稳定快照自动进入 `completed`；115 文件树实见 6 个文件、约 210.6 MB，全程未使用人工完成。
