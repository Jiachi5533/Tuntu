# ADR-001：内容身份与全局去重

- 状态：已接受
- 日期：2026-08-13
- 适用版本：v0.1

## 背景

同一内容可能以不同大小写、分隔符或补零形式出现在多个榜单中；同一 BTIH 也可能通过带有不同显示名称、Tracker 和参数顺序的 magnet 被多个候选源返回。如果只按原始标题、链接或 Profile 目录去重，会造成重复查询和重复下载。

## 决策

1. `ContentItem` 使用 `namespace + normalized_key` 作为稳定身份。
2. Provider 同时提供 `raw_key` 与 `normalized_key`，并负责来源特有的规范化规则。
3. 无法可靠规范化时使用“来源命名空间 + 原始 ID”，核心不做模糊猜测。
4. v0.1 的 `Candidate` 只使用规范化 BitTorrent v1 BTIH 作为身份。
5. 40 位十六进制和 32 位 Base32 BTIH 统一转换成小写十六进制。
6. magnet 的显示名称、Tracker 和参数顺序不参与身份；相同 BTIH 合并来源证据。
7. 在唯一 CloudDrive2 实例范围内，同时按 ContentItem 和 BTIH 做跨 Profile 全局幂等。
8. 一个内容的任务被 CD2 接受后，不再自动为它切换其他 BTIH。
9. 用户可以二次确认后强制重提；新任务必须关联旧任务并记录审计事件。

## 结果

- 多榜单和多候选源可以安全合并，Profile 目录差异不会触发重复自动下载。
- Provider 规范化错误可能造成误合并或漏合并，因此必须保存原始标识和来源证据并使用 Fixture 测试。
- 数据库需要 ContentItem、BTIH 唯一约束，以及提交前的事务化幂等占位。
- 未来增加多个下载器实例时，幂等范围必须重新明确，不能直接套用 v0.1 假设。

## 不采用的方案

- 按标题模糊匹配：误合并风险不可控。
- 按完整 magnet URI 去重：Tracker 和参数差异会产生重复任务。
- 只在单个 Profile 内去重：不同订阅目录仍会重复下载。
