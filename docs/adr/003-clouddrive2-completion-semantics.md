# ADR-003：CloudDrive2 完成语义

- 状态：已接受
- 日期：2026-08-13
- 适用版本：v0.1

## 背景

CloudDrive2 接受 magnet 只证明提交请求成功，不证明离线下载已开始，更不证明目标文件已经完整保存到 115。Tuntu 的核心需求包含“哪些下过、哪些没下过”，因此完成状态必须有可验证依据。

## 决策

1. DownloadTask 使用 `submitting`、`submitted`、`downloading`、`completed`、`failed` 和 `attention_required`。
2. `submitted` 只表示 CD2 明确接受任务。
3. `downloading` 需要 CD2 或等价可靠来源提供进行中证据；若不可观察，可从 `submitted` 直接到 `completed`。
4. `completed` 只允许两类自动证据：
   - CD2 任务 API 明确返回完成；或
   - 相对提交前目录基线新增或变化的文件集合、文件数和总大小，在可配置且不少于两次的成功观察之间保持稳定。
5. 轮询间隔和“需要关注”超时均为系统配置项，默认分别为 5 分钟和 24 小时；超时后转为 `attention_required`，但保留内容和 BTIH 去重锁。
6. 用户可以二次确认后手工标记完成；状态事件必须标注人工来源。
7. 网络超时或提交结果不明时只反查和重试原候选，不切换 BTIH。
8. CD2 接受后的任务失败必须人工处理，不自动换 magnet。
9. M1 实测选择方案 B：`AddOfflineFiles` 提交响应 + 目标目录基线差异和文件稳定检测。当前 115 实例的 `ListOfflineFilesByPath` 在 8/30/60 秒 Deadline 下均超时，因此任务 API 只作为可选增强，不能成为唯一信号。
10. 受限 API Token 的宿主根目录在 gRPC 中映射为虚拟根 `/`；路径构建使用 Token 视角，禁止再次拼接宿主绝对根目录。
11. 同一目标目录存在并发写入、无法唯一归因或观察结果不一致时，不得自动标记完成，转为 `attention_required`。
12. 文件回退方案在无法从任务 API 取得可靠归属前，对目标目录建立提交互斥；首次观察到变化后固定任务顶层路径，后续只跟踪这些路径。CD2 返回目标目录之外的路径时拒绝本次观察。

## 结果

- 用户看到的完成状态可追溯到明确证据。
- 实现必须保留外部任务引用、轮询证据、错误分类和状态事件。
- 文件稳定检测必须保存提交前基线，防止把临时文件、未完成写入或同名旧文件误判为完成。
- 人工完成可处理黑盒客户端限制，但不能替代 v0.1 的自动完成能力。

## 不采用的方案

- CD2 返回 HTTP 2xx 就标记完成：语义错误。
- 固定时间后自动假设完成：没有证据。
- 提交超时后自动换另一个 magnet：可能造成重复下载。
